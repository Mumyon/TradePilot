# 실제 시세 기반 TradePilot 모의투자

## 이번 구현 범위

한국투자증권(KIS)의 KRX 체결 시세를 서버에서 한 번 구독하고, 기존 앱 WebSocket으로 전달합니다. 주문 전 Pilot 점검 → 사용자 확인·이유 → 지정가 모의주문 → 새 시세 조건 충족 시 가상 체결 → 수수료·손익·피드백 기록의 기존 흐름을 사용합니다.

실계좌 조회·잔액 조회·실주문·증권사 모의주문 API는 호출하지 않습니다. 거래는 TradePilot 내부 가상 계좌에서만 일어납니다. MAP 웹페이지는 작업 대상이 아닙니다. 기존 ChatGPT 연결은 종료된 연구 실험 복기용이며 일반 주문 전 AI 상담 기능으로 바뀐 것은 아닙니다.

## 연결 준비와 실행

1. [한국투자증권 Open API](https://apiportal.koreainvestment.com/)에서 API 이용 신청과 **실제 시세용 앱 키·앱 시크릿**을 준비합니다. 계좌/API 이용 자격은 제공처에서 확인해야 합니다. 이 준비는 TradePilot에 실주문을 허용하는 것과 별개입니다. 다른 제공처를 선택하면 해당 어댑터가 추가로 필요합니다.
2. 프로젝트의 `server/.env.market` 파일에 아래 내용을 직접 입력합니다. 키를 채팅, 화면 캡처, Git에 넣지 마세요. 해당 파일은 Git 제외 대상입니다. `chmod 600 server/.env.market`로 읽기 권한을 제한하세요.

```dotenv
KIS_APP_KEY=여기에_실제_앱키
KIS_APP_SECRET=여기에_실제_앱시크릿
KIS_SYMBOLS=["005930","000660"]
```

3. 프로젝트 루트 터미널에서 서버 실행:

```sh
./tool/start_market_paper.sh --provider kis
```

4. 다른 터미널에서 iPhone 시뮬레이터 앱 실행:

```sh
./tool/start_ios_market_paper.sh
```

여러 기기가 있으면 명령 뒤에 원하는 시뮬레이터 ID를 붙입니다. 로컬 Python 환경은 기존 `.venv`와 `pgserver`를 사용합니다. 새 환경은 `cd server` 후 `uv sync --group postgres-test`로 설치합니다.

- 주소: `http://127.0.0.1:18082`. 기존 합성 시연 서버 18081과 분리됩니다.
- 데이터: `server/.paper-market/kis/postgres`. 기존 `server/.demo/postgres`를 수정하지 않습니다.
- 나무 기본 설정은 기존 TradePilot `.demo/postgres` 계정·모의잔고 DB를 사용합니다. 앱에서 기존 TradePilot 계정으로 로그인하세요. KIS 모드는 별도 `.paper-market/kis` DB를 사용합니다.
- 기본 종목은 삼성전자·SK하이닉스입니다. 추가 코드는 KIS_SYMBOLS에 지정 후 재시작하고 관심종목에 추가합니다. 현재 종목명 사전은 두 종목만 제공하며 추가 종목은 코드로 표시됩니다. 앱 설정의 서버 상태에서 수신 상태를 확인할 수 있습니다.
- 일반 배포 서버에는 `MARKET_DATA_MODE=kis`와 동일한 키 환경변수를 설정합니다. **단일 서버 프로세스/worker**로 실행하세요. 여러 프로세스 간 수신 리더 선출은 아직 구현하지 않았습니다.

## 데이터와 모의 체결의 의미

- 공식 `H0STCNT0`의 영업일자·체결시각을 KST로 해석해 UTC 저장합니다. 수신 시간을 거래 시각으로 덮어쓰지 않습니다.
- 초기 범위는 KRX 연속매매 09:00~15:20입니다. 종가 동시호가·시간외·NXT는 제외합니다. 특수 개장일의 별도 세션 달력은 미구현입니다. 시장 휴장 시 거래가 수신되지 않으므로 가격이 임의로 생성되지 않습니다.
- 15초보다 오래된 입력은 거절합니다. 주문·체결 시에도 기존 freshness 검증을 적용합니다. 끊어진 직후에는 마지막으로 검증된 시세가 최대 설정 허용 시간(기본 15초)까지 사용될 수 있습니다.
- 새 시세는 작업자가 약 2초마다 DB에 반영하고 앱으로 전파합니다. 모든 체결 틱을 영구 저장하는 시스템은 아닙니다. 같은 초의 최신 가격으로 갱신하지만 주문은 주문 접수 시각보다 **뒤의** 거래 시각에서만 체결합니다.
- 체결은 지정가 조건을 만족하면 전량 체결하는 단순 모형입니다. 호가 잔량·대기 순서·슬리피지·시장 충격을 재현하지 않습니다. 실제 투자 수익과 동일하다고 해석하면 안 됩니다.
- 실제 시세 가격과 가상 주문/잔고를 분리합니다. 시세 공급자를 켜도 ExecutionPort는 미설정 상태입니다.

## 차트와 피드백 준비 시간

- 실제 체결 스트림의 가격과 누적 거래량 차이로 1분·5분·15분·1시간 봉을 쌓습니다. 시작 시점의 부분 봉, 재연결로 끊긴 부분 봉은 완성 봉으로 저장하지 않습니다. 과거 분봉 REST 백필과 일봉은 이번 단계에 포함하지 않았습니다.
- 다음 구간의 첫 틱을 받아야 이전 봉이 확정됩니다. 체결이 없는 구간은 가짜 봉으로 채우지 않습니다. 장 종료 직전 미확정 봉은 확정 자료로 사용하지 않습니다.
- 10분 가격변화 피드백은 실제 비교 자료가 쌓이기 전에는 평가 불가로 남습니다. 과매매·계획 등 기존 주문 기록 기반 점검은 별도로 동작합니다. 일반 모의계좌의 거래 설정(주문한도·일일 손실한도·쿨다운·거래 원칙·개인 주문정지)은 삭제되었습니다.
- AI 예측은 최소 35개 연속 완성 5분봉, 동일 데이터 출처로 학습한 품질 기준 통과 모델 등 기존 조건을 충족해야 합니다. 이번에는 새 모델을 학습하거나 기존 Yahoo 출처 모델을 KIS 데이터로 강제 전환하지 않았습니다.

## 장중 확인 순서

1. 앱 서버 상태: `market_data_mode=kis`, `mode=paper`, `real_broker_configured=false` 확인.
2. 관심종목의 가격과 시각이 장중에 실제로 변하는지 확인.
3. 주문 전 Pilot 점검을 열어 데이터 부족/경고·한도 표시 확인.
4. 가상 금액의 소량 주문을 접수하고 다음 시세 조건 충족 후 체결·수수료·잔고·일지 확인.
5. 서버 네트워크를 끊었을 때 시세가 오래되면 주문이 차단되는지 확인.

실제 키를 사용한 장중 수신 검증은 아직 수행하지 않았습니다. 단위·DB 테스트는 공식 메시지 형태를 따른 **합성 테스트 입력**으로 수행하며 실제 연결 성공 증거가 아닙니다.
