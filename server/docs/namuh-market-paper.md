# 나무 PLUG 실제 시세 + TradePilot 모의투자

2026-11-08 기준. 실주문은 후속 단계로 둡니다. MAP 웹페이지는 사용하지 않습니다.

## 계좌를 구분하세요

| 항목 | 이번 사용 여부 |
|---|---|
| 나무 PLUG 앱 키·시크릿 | 인증·실제 시세 조회에 사용 |
| 나무 실계좌 | 계좌 조회·잔고·실주문 사용 안 함 |
| 나무에서 발급한 모의투자 계좌 | 향후 증권사 주문 API 검증에 사용 가능. 이번에는 연결 안 함 |
| TradePilot 내부 모의계좌 | 가상 1천만 원으로 주문 전 피드백·모의 체결·손익 기록 |

실제 시세 서버에 접속하는 것과 실주문을 보내는 것은 별개입니다. 이 어댑터의 HTTP 경로는 토큰 발급과 시세 기간조회만 허용하고, WebSocket은 KRX 체결가 `oc`만 구독합니다. 계좌번호를 입력받거나 계좌 목록을 조회하지 않습니다. ExecutionPort도 미설정 상태를 유지합니다.

## 설정·실행

프로젝트 루트에서 실행합니다.

```sh
cd /Users/mumyon/Documents/TradePilot
./tool/configure_namuh.sh
```

입력 프롬프트에 App Key와 App Secret을 붙여넣습니다. 입력 내용은 화면에 보이지 않습니다. `server/.env.namuh`에 권한 600으로 저장되며 Git 제외 대상입니다. **키를 채팅에 보내거나 스크린샷에 포함하지 마세요.** 이미 저장한 값을 고칠 때:

```sh
./tool/configure_namuh.sh --replace
```

이 명령은 기존 키를 새 입력으로 교체하고 기존 종목 설정을 유지합니다. 다음으로 최대 약 30초 동안 인증·시세 구독만 확인합니다.

```sh
./tool/check_namuh.sh
```

결과에는 구독 성공과 실제 체결 데이터 수신을 따로 표시합니다. 장이 닫혀 있으면 구독 성공 후에도 체결 시세는 없을 수 있습니다. 점검 결과는 `server/.paper-market/namuh-connection-status.json`에 저장되며 키·토큰은 포함하지 않습니다.

인증·구독이 확인되면 서버와 앱을 각각 다른 터미널에서 실행합니다.

```sh
./tool/start_market_paper.sh
```

```sh
./tool/start_ios_market_paper.sh
```

- 나무가 기본 제공처입니다. 서버 주소는 `http://127.0.0.1:18082`입니다.
- 서버는 기존 `server/.demo/postgres` TradePilot 계정·모의투자 DB를 사용합니다. 기존 TradePilot 로그인과 가상 잔고를 이어 씁니다. 나무 앱 키는 시세 연결에만 사용하고 TradePilot 사용자 계정과 별도로 관리합니다.
- 앱의 이전 로그인은 로그아웃한 후 이 서버에서 회원가입·로그인하세요. 나무 계좌 비밀번호가 아닌 **TradePilot 앱 계정**입니다.
- 앱 설정의 서버·데이터 상태에서 `나무 PLUG KRX`, 구독/수신 상태, 모의투자 방식을 확인합니다.
- 기본 종목은 삼성전자·SK하이닉스입니다. 추가하려면 `.env.namuh`의 `NHPLUG_SYMBOLS`를 수정하고 재시작하세요. 현재 추가 종목명은 코드로 표시됩니다.
- 하단 `발견` 화면은 `/v1/market/discover`에서 나무 PLUG 국내주식 현재가 API의 누적 거래대금·거래량·등락률을 정렬합니다. API 등록 종목만 포함하며 기본은 삼성전자·SK하이닉스 2종목이므로 전 시장 순위로 해석하면 안 됩니다. 화면은 15초마다 새로고침하고 서버 응답은 10초 캐시합니다. 장외에는 마지막 거래일 누적값을 표시하고 실시간 체결 수신과 구분합니다.
- 기존 KIS 어댑터는 `./tool/start_market_paper.sh --provider kis`로 선택할 수 있습니다. 나무·KIS 서버를 같은 18082 포트에 동시에 실행하지 않습니다.
- 새 개발 환경에는 `cd server` 후 `uv sync --group postgres-test`로 의존성을 설치합니다. 나무 TLS 검증에는 truststore를 사용합니다. 인증서 검증을 끄지 않습니다.
- 다중 서버 프로세스의 수신 리더 선출은 아직 없습니다. 로컬 단일 서버 프로세스로 실행합니다.

## 인증 오류 확인

- `IGW40031`: App Key가 유효하지 않다는 나무의 응답입니다. 나무 PLUG에 표시된 키인지, 복사 누락·공백·다른 항목 입력이 없는지 확인하고 로컬에서 재설정합니다.
- `IGW40032`: App Secret 확인이 필요합니다.
- `IGW40301`: API 사용 권한 확인이 필요합니다.
- 인증 요청이 HTTP 400/401/403으로 거절되면 자동 반복을 중단합니다. 수정 후 진단 도구 또는 서버를 다시 실행하세요.
- 일반 오류의 원문·URL 쿼리·토큰·키는 출력하지 않습니다. HTTP 상태와 공개 형식의 오류 코드만 남깁니다.
- 접근토큰은 앱 키·시크릿 조합별 별도 파일에 권한 600으로 저장해 재사용합니다. 파일 잠금을 사용하고 만료 및 HTTP 401일 때 갱신합니다. 유량 초과로 토큰을 반복 발급하지 않습니다.

## 시세 처리와 피드백

1. 공식 토큰 발급 → 종목별 영업일·연속매매 시작·종가 동시호가 시작시각 조회 → KRX 실시간 체결가 구독.
2. 나무 WebSocket 메시지의 `time`에는 날짜가 없습니다. 별도 조회의 `bsop_date`와 결합하며, 그 날짜가 현재 KST 날짜와 다르면 현재 시세로 채택하지 않습니다. 시간도 현재보다 15초 넘게 지연되거나 2초 넘게 미래이면 거절합니다.
3. 같은 종목의 다른 출처 시세를 섞지 않습니다. 나무 모드 주문과 평가에는 `namuh_krx` 출처만 사용합니다.
4. 실제 수신 스트림에서 1분·5분·15분·1시간 봉을 생성합니다. 시작 부분 봉과 재연결로 누락될 수 있는 봉은 확정하지 않습니다. REST 기간조회는 영업일·장 시간 확인용이며 과거 차트 백필은 아직 연결하지 않았습니다.
5. 작업자가 약 2초마다 최근 가격과 완성 봉을 저장합니다. 앱은 기존 서버 WebSocket으로 받습니다. 모든 개별 틱을 영구 보관하는 구조는 아닙니다.
6. 주문 전 Pilot 점검 → 경고·판단 이유 → 모의주문 접수 → 이후 시세가 지정가 조건을 만족하면 전량 가상 체결 → 손익·피드백 기록.

시세 공백 시 10분 변화율은 평가 불가로 남습니다. AI 예측은 충분한 연속 5분봉과 **같은 출처로 학습한 검증 통과 모델**이 필요합니다. 나무 연결만으로 예측이 자동 활성화되거나 투자 성과 개선이 입증되는 것은 아닙니다.

모의 체결은 호가 잔량·부분 체결·대기 순서·시장 충격을 재현하지 않는 단순 모형입니다. 서버의 기존 편도 수수료 0.015%를 적용하며 나무 실계좌의 수수료 조건을 반영한 값은 아닙니다. NXT·통합시장·동시호가·시간외 거래는 이번 범위에서 제외합니다.

## 실주문을 미룬 이유와 순서

실주문 호출 코드보다 다음 항목의 구현·검증이 더 큽니다. 현재 사용자의 핵심 목적(실제 시세에서 주문 전 피드백과 성과 기록)을 먼저 확인합니다.

1. 나무 모의투자 환경에서 계좌 종류 검증 및 조회 전용 잔고 대조.
2. 별도 주문 식별·상태 저장, 전송 결과 불명 상태 조회, 중복 전송 방지.
3. 부분 체결·정정·취소·체결 통보와 잔고 재대조.
4. 연결 장애·서버 재시작·토큰 만료 복구와 주문 한도·긴급 정지 검증.
5. 위 검증 후 실주문 범위·금액·활성화 절차를 확정. 현재는 실주문을 호출할 수 없습니다.
