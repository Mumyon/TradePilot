# TradePilot v2 적용 방법

## 2.0.3 자기 화면 이동 오류 수정

활성 탭의 자기 화면 이동과 수량 상·하한의 자기 상태 전환은 연결하지 않습니다. 13개 불필요한 연결을 제외한 **213개 연결**을 저장합니다. 모든 이동 대상이 같은 페이지의 다른 최상위 프레임인지 검사하고, 기존 프레임 내부 갱신 후에도 연결이 유지되는지 재검증합니다.

기존 오류창을 닫고 **TradePilot UI Generator**를 다시 실행하세요. 완료창에서 **빌드 2.0.3 · 35개 화면/상태 · 213개 클릭 연결 저장 확인**을 확인한 뒤 Present를 새로 여세요. 기존 프레임 갱신·재실행·빈 파일 생성에 대한 로컬 검증을 수행했습니다. 실제 Figma 실행은 아직 확인하지 못했습니다.

## 2.0.2 팝업 연결 오류 수정

사용자 실행에서 확인된 오류: `overlayRelativePosition`은 수동 배치(`MANUAL`) 팝업에만 허용됩니다. 기본 배치 팝업에 좌표를 지정했던 코드를 제거했습니다. 이전 코드는 이 제약에서 실패하는 것을 테스트로 재현했고, 수정 코드의 226개 연결은 해당 제약을 통과했습니다. 실제 Figma 재실행 확인은 필요합니다.

기존 오류창을 닫고 **TradePilot UI Generator**를 다시 실행하세요. 완료창의 **빌드 2.0.2**를 확인한 뒤 Present를 새로 열면 됩니다. 등록된 폴더가 `/Users/mumyon/Documents/TradePilot/output/TradePilot-Figma-UI`라면 재등록은 필요하지 않습니다.

## 2.0.1 오류 표시 수정

`error.message`가 없는 문자열/객체 오류도 원본 내용을 표시합니다. 오류창에 빌드 번호, 실행 단계, 화면, 요소, API 작업이 나타납니다. 이 진단을 통해 2.0.2에서 위 팝업 연결 오류를 수정했습니다.

이미 등록해 둔 **TradePilot UI Generator**를 현재 Figma Design 파일에서 다시 실행하세요. 로컬 `code.js`를 수정해도 기존 캔버스는 자동으로 바뀌지 않습니다. 반드시 플러그인을 한 번 실행해야 합니다.

1. 열어 둔 Present 창을 닫습니다.
2. 원래 디자인 편집 화면에서 `Plugins → Development → TradePilot UI Generator` 실행.
3. **TradePilot v2 적용 완료 — 빌드 2.0.3 · 35개 화면/상태 · 213개 클릭 연결 저장 확인** 메시지를 확인합니다.
4. 완료창을 닫고, 자동 선택된 **01 · 관심종목** 프레임에서 오른쪽 위 **▶ Present** 실행.
5. 프레젠테이션의 흐름 목록에서는 **TradePilot v2 · 시작** 또는 **TradePilot v2 · 검색과 주문**을 선택합니다.

위 완료 메시지가 보이지 않으면 새 코드가 실행되지 않았거나 실행 중 오류가 발생한 것입니다. `Plugins → Development → Import plugin from manifest…`로 이 폴더의 `manifest.json`을 다시 등록하고 실행하세요.

## 추가된 동작

- 하단 5개 탭: 관심종목 / 차트 / 자동매매 / 매매일지 / 전체 메뉴
- 차트의 검색창 → 종목 검색 팝업 → 삼성전자 또는 SK하이닉스 차트
- 검색 팝업의 입력란 클릭 → “삼성” 검색 결과 예시, 다시 클릭 → 전체 예시 목록
- 매수 / 매도 → 주문 상세 팝업 → 수량 1주 또는 5주 선택 → 금액 변경 → 주문 확인 → 모의 접수 완료
- 팝업 닫기: × 또는 팝업 바깥 영역
- 주문 완료 → 차트 또는 매매일지
- 전체 메뉴 → 검색 / 관심종목 / 자동매매 / 매매일지 / 기존 거래 전 점검 체험

검색 자유 입력, 임의 가격·수량 입력, 실제 시세·주문 전송은 구현하지 않은 Figma 프로토타입입니다. +는 5주, −는 1주 예시로 전환합니다. 종목별 가격과 주문 금액은 팝업·확인·접수 화면에서 일치합니다. 기존 NAVER/Apple 행은 상세 화면이 없으므로 전환을 연결하지 않았습니다.

## 전환 점검 및 수정

2.0.1 사용자 실행 결과, 첫 팝업 연결에서 잘못된 수동 좌표 지정으로 `setReactionsAsync`가 실패한 것을 확인했습니다. 2.0.2에서 해당 좌표를 제거했습니다. 최초 v1의 미작동까지 같은 원인이었는지는 확인되지 않았습니다.

- 모든 클릭 영역을 각 프레임의 최상단 `Tap / …` 레이어에 명시했습니다. 아이콘·텍스트 사이 빈 공간도 눌립니다.
- 연결 저장 직후 Figma의 `reactions` 값을 다시 읽어 대상과 동작을 검증합니다. 저장이 실패하면 완료로 표시하지 않습니다.
- Present 시작 프레임과 이름이 명확한 두 개의 흐름을 설정합니다.
- 원래 6개 프레임은 이름으로 찾아 기존 ID와 위치를 유지하면서 내부를 갱신합니다. 새 팝업과 상태 프레임은 옆에 추가합니다. 기존 프레임 이름을 바꾸었다면 자동 매칭되지 않으므로 새 프레임이 생길 수 있습니다.
- 갱신 전 기존 화면 복사본을 숨겨진 `TradePilot / backup before v2 / …` 프레임에 보관합니다. 다시 실행하면 해당 이름의 v2 프레임을 갱신합니다.

## 검증 상태

로컬 검증: 35개 상태 전체 도달 가능, 226개 연결 대상, 팝업 대상 유형, 화면 경계, 연결 읽기 검증, 기존 프레임 ID 유지, 재실행 중복 방지, 변수 중복 방지, 연결 실패 시 원래 화면 보존을 검사했습니다. API 테스트 대역을 사용했으므로 실제 Figma 실행을 대체하지 않습니다.

PNG의 메뉴·차트·검색·주문 팝업 레이아웃을 시각 검토했습니다. Figma MCP Starter 호출 한도 및 데스크톱 제어 연결 문제로 실제 Present 클릭 테스트는 완료하지 못했습니다.
