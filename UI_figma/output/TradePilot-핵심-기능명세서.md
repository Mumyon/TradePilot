# TradePilot 핵심 기능명세서

> AI 주식 예측 및 뇌동매매 방지 의사결정 보조 시스템  
> 캡스톤디자인 제안서와 기존 TradeGuard AI 기능명세서를 바탕으로 핵심 기능을 재정리한 문서. 서비스명은 UI 견본에 맞춰 **TradePilot**으로 통일한다.

## 1. 개발 배경 및 목적

초보 투자자는 급등한 종목을 뒤늦게 매수하거나, 급락 시 두려움 때문에 계획 없이 매도하고, 손실을 만회하려고 거래를 반복할 수 있다. 주가 예측만 제공하면 AI 결과에 지나치게 의존할 수 있으므로, **시장 전망과 사용자의 거래 행동을 함께 점검하는 기능**이 필요하다.

TradePilot은 시장 데이터를 활용해 향후 주가 방향의 확률을 제시하고, 주문 직전 사용자의 거래가 사전에 정한 원칙을 벗어나는지 확인한다. 거래 이후에는 당시 예측·주문 이유·실제 결과를 함께 기록하여 매매 습관 개선을 돕는다.

**핵심 흐름:** 종목 선택 → AI 예측 확인 → 주문 입력 → 뇌동매매·위험 점검 → 모의주문 최종 확인 → 매매일지 및 피드백

초기 구현은 모의투자를 기본으로 한다. 자동매매·실계좌 연동·복잡한 전략 편집은 후속 확장으로 두고, AI 예측과 거래 전 점검을 우선 완성한다.

## 2. 핵심 기능 범위

| ID | 기능 | 핵심 요구사항 |
|---|---|---|
| F-01 | 종목 및 시세 조회 | 종목 검색, 가격·거래량·차트와 데이터 기준 시각 표시 |
| F-02 | AI 주식 예측 | 다음 구간의 상승·중립·하락 확률과 판단 근거 제공 |
| F-03 | 뇌동매매 점검 | 급등 추격·공포매도·복수매매·과매매 가능성 및 해당 근거 표시 |
| F-04 | 위험 점검 및 모의주문 | 주문한도·손실한도·중복주문·쿨다운·거래 정지 상태 검사 후 주문 처리 |
| F-05 | 매매일지 및 피드백 | 당시 AI 예측, 사용자 판단, 경고, 거래 결과를 저장·비교 |

로그인, 거래 원칙 및 위험한도 설정은 위 기능을 위한 기본 지원 기능으로 포함한다. 상세 API·DB 설계와 관리자 기능은 본 핵심 명세에서 생략한다.

## 3. AI 주식 예측

### 3.1 예측 대상과 처리 기준

**목적:** 사용자가 거래 전에 다음 구간의 시장 방향과 불확실성을 확인하도록 한다.

| 항목 | 요구사항 |
|---|---|
| 입력 | 과거 가격·거래량, MA5·MA20, RSI, MACD, 가격 및 거래량 변화율 |
| 예측 단위 | 초기안은 완성된 5분봉으로 분석하고, 이후 1시간의 가격 방향을 예측 |
| 학습 정답 | 기준 종가 대비 12개 봉 이후 종가 수익률이 +0.5% 초과이면 상승, -0.5% 미만이면 하락, 그 사이이면 중립 |
| 결과 | 상승·중립·하락 확률, 예측 생성 시각, 대상 기간, 모델 버전 |
| 방향 표시 | 가장 높은 확률이 65% 이상이면 해당 방향 표시. 미만이면 ‘방향 판단 보류’ 표시 |
| 근거 | 예측 시점의 주요 지표와 모델 분석에서 확인한 영향 요인 제시. 단순 지표 요약과 모델 설명을 구분 |
| 예외 | 필요한 봉 부족, 시세 누락·지연, 모델 오류 시 ‘분석 불가’ 표시. 이전 결과를 최신 예측처럼 제시하지 않음 |

**5분봉·1시간·±0.5%·65%는 원문에 확정되지 않은 초기 설계 제안값이다.** 학습·검증 결과에 따라 조정하고, 최종 시험 전 고정한다. 장 마감까지 1시간이 남지 않은 경우에는 신규 예측을 제공하지 않는 것을 초기 기준으로 한다.

‘중립’은 가격 변화가 작은 것으로 예측한 결과이고, ‘판단 보류’는 특정 방향을 제시하기에 확률이 부족한 상태이다. AI 상승 확률을 매수 명령이나 사용자의 뇌동매매 점수로 직접 변환하지 않는다.

### 3.2 예측 검증 및 표시 원칙

- 데이터를 시간 순서대로 학습·검증·시험 구간으로 분리하고, 입력에는 예측 시점까지 확인된 정보만 사용한다. 구간 경계에서는 미래 1시간의 정답 기간이 겹치는 표본을 제외한다.
- 단순 기준모델과 비교하여 방향 분류 성능, 클래스별 성능, 확률의 실제 적중 비율을 평가한다. 검증 구간을 순차적으로 이동하는 방식으로 성능의 일관성도 확인한다.
- 기존 명세의 별도 ‘신뢰도 64%’처럼 산출 근거가 없는 수치는 표시하지 않는다. 예측 확률과 과거 검증 성능을 구분하고, 검증 성능에는 평가 기간·표본 수를 함께 제시한다.

**UI 사용 상황 — 종목 상세 및 AI 분석:** 관심 종목을 선택하거나 주문 전에 시장 전망을 확인할 때 아래 화면을 사용한다. 하단 AI 카드에 대상 기간·방향 확률·근거를 제시한다. 견본의 ‘다음 1시간 상승 가능성 62%’는 제안 기준상 ‘방향 판단 보류’에 해당한다. 3개 방향 확률, 기준 시각, 검증 성능 확인 영역은 추가가 필요하다.

## 4. 뇌동매매 판단 기준 및 거래 전 점검

### 4.1 판단에 필요한 정보

주문 방향·금액·시각, 최근 시세 변화, 보유 종목 평가손익, 최근 체결 및 청산 기록, **주문 전에 저장한 매매 계획**을 사용한다. 계획에는 진입 조건·손절 기준·분할매매 여부를 저장한다.

뇌동매매는 감정을 확정하는 진단이 아니라 **관찰 가능한 행동에 대한 경고**로 정의한다. 가격이 하락했다는 이유만으로 공포매도라고 판단하지 않으며, AI 예측과 다르게 거래했다는 사실도 뇌동매매 근거가 되지 않는다.

### 4.2 유형별 탐지 기준

아래 조건은 모두 주문 제출 직전에 검사한다. 급등·급락 수치와 계획 예외는 이번 명세에서 구체화한 **초기 검증용 제안**이며, 검증된 보편적 투자 기준을 의미하지 않는다.

| 유형 | 1차 탐지 조건 | 계획 확인 및 오탐 방지 | 점수 |
|---|---|---|---:|
| 급등 추격 매수(FOMO) | 매수 요청 **AND** 최근 10분 가격 상승률 ≥ 3% | 급등 이전에 저장된 진입 조건을 충족한 계획 매수이면 점수 제외 | +30 |
| 공포매도 | 매도 요청 **AND** 최근 10분 가격 하락률 ≤ -3% **AND** 보유 평가수익률 < 0% | 급락 이전에 저장된 손절·분할청산 조건을 충족하면 ‘계획된 매도’로 처리하고 점수 제외 | +30 |
| 복수매매 | 최근 청산 거래 3건 연속 실현손실 **AND** 마지막 손실 확정 후 30분 이내 신규·추가 매수 요청 | 손실 이후 보유량을 줄이는 매도는 제외. 손실 이전에 등록된 분할매수 계획에 따른 주문은 점수 제외 | +25 |
| 과매매 | 현재 주문을 포함하여 최근 60분 내 접수된 주문이 5건 이상 | 같은 주문의 재전송은 1건으로 계산. 거절 주문은 제외하고, 사전에 등록된 분할주문은 하나의 계획으로 집계 | +20 |
| 매매 계획 위반 | 주문 방향·가격·금액 등이 사전에 저장한 조건을 벗어남 | 계획이 없으면 ‘계획 미등록’으로 표시하며 위반으로 단정하지 않음 | +20 |

가격 변화율은 `(현재가 / 10분 전 가격 - 1) × 100`으로 계산한다. 최근 손실은 수수료를 반영한 청산 거래 기준이며, 부분 체결은 같은 청산 주문 단위로 합산한다. 필요한 데이터가 없으면 해당 유형은 ‘판단 불가’로 남기며, 이를 위험 없음으로 표시하지 않는다.

계획이 없는 경우에는 가격·행동 조건에 따른 **가능성 경고**를 제공한다. 주문 직전에 새로 작성한 이유만으로 경고를 자동 해제하지 않는다. 매수 화면을 반복해서 열었다는 행동은 보조 정보로만 사용한다.

### 4.3 점수와 사용자 안내

점수는 기존 명세의 가중치를 유지하며, 각 유형을 주문당 한 번만 합산하고 최대 100점으로 제한한다. 점수는 감정적 거래일 확률이 아니다.

| 합산 점수 | 상태 | 처리 |
|---|---|---|
| 0~29점 | 낮음 | 탐지된 항목이 있다면 근거를 표시하고 일반 확인 진행 |
| 30~59점 | 주의 | 유형·수치·계획 충족 여부를 설명하고 거래 이유 재확인 |
| 60~100점 | 높음 | 추가 확인 단계에서 계획과 주문 내용을 다시 확인한 후 진행 여부 선택 |

일부 분석이 불가능하면 점수와 함께 ‘일부 판단 불가’를 표시한다. **행동 경고는 재확인을 유도하고, 주문 차단은 별도의 위험 규칙으로 결정한다.** 위험 규칙 위반은 사용자 확인만으로 해제되지 않는다.

**공포매도 예시:** 10분간 -3.5% 하락하고 보유 평가수익률이 -2%인 종목을 매도하려는 경우, 계획된 청산 조건이 확인되지 않으면 공포매도 가능성으로 +30점을 부여한다. 같은 주문이 사전에 등록한 손절 조건을 충족한다면 ‘계획된 손절’로 처리하여 해당 점수를 부여하지 않는다.

**UI 사용 상황 — 거래 전 점검:** 주문 가격·수량을 입력한 뒤 아래 화면에서 탐지 이유, 주문 요약, 위험한도, 사용자 거래 근거를 확인한다. 공포매도일 때는 제목을 ‘잠깐, 계획된 매도인가요?’로 바꾸고 하락률·평가손익·손절 조건을 보여준다. 견본의 ‘30분간 4.2% 상승’은 예시이므로 실제 구현에서는 본 명세의 10분 기준으로 통일한다. 총점·유형별 점수·추가 확인 상태도 보완한다.

## 5. 위험 점검 및 모의주문

감정 분석 이후 아래 규칙을 검사하고, 최종 확인 시 최신 잔액·보유량·시세로 다시 검증한다.

| 검사 | 처리 기준 |
|---|---|
| 1회 주문한도 | 주문금액이 사용자가 설정한 한도를 초과하면 거절 |
| 일일 손실한도 | 당일 순실현손익이 설정 손실한도의 음수값 이하이면 신규·추가 매수 차단. 보유량을 줄이는 매도는 허용하는 것을 초기 정책으로 제안 |
| 중복주문 | 동일 주문 식별자로 재요청하면 기존 처리 결과 반환, 중복 실행 금지 |
| 주문 쿨다운 | 동일 종목·방향 주문 접수 후 설정 시간 내 반복 주문 제한. 초기 예시 5분, 계획된 위험 축소 매도는 예외 |
| 거래 정지 | 장애 또는 사용자 정지 시 신규 자동주문 중단. 수동 모의주문도 데이터·잔액 검증이 불가능하면 접수 중단 |

가상 잔액 부족 또는 보유 수량을 초과한 매도도 거절한다. 주문 접수와 체결을 구분하고, 지정가 주문은 가격 조건 충족 시 체결한다. 거절·취소·미체결 주문을 체결 내역으로 기록하지 않는다.

**UI 사용 상황 — 최종 주문 확인:** 거래 전 점검을 통과한 뒤 아래 화면에서 종목·방향·가격·수량·예상 금액을 확인하고 사용자가 모의주문을 확정한다. 경고 확인 이후에도 위험 규칙을 위반하면 차단 이유를 표시한다. 견본은 ‘체결 기능 없음’인 데모 화면이므로, 실제 구현에서는 접수·체결 결과 화면을 별도로 연결한다.

## 6. 매매일지 및 피드백

주문 당시의 AI 예측·확률·모델 버전, 사용자 거래 이유, 적용 계획, 탐지 유형·점수·기준값, 위험 검사 결과, 체결 여부와 손익을 저장한다. 이후 모델이나 판단 기준이 바뀌어도 당시 기록은 유지한다.

피드백은 다음 세 가지에 집중한다.

- **예측과 결과:** 당시 1시간 예측과 실제 1시간 후 가격 방향을 비교한다. 보유 기간이 다른 거래 손익과 AI 방향 적중 여부는 구분한다.
- **원칙 준수:** 계획이 등록되어 있고 평가 가능한 거래 중 계획을 지킨 거래의 비율을 계산한다. 계획 미등록 거래는 따로 표시한다.
- **반복 행동:** 뇌동매매 경고 유형별 횟수, 경고 후 주문 취소·진행 여부를 보여주고 다음 거래에서 확인할 원칙을 제안한다.

**UI 사용 상황 — 거래 복기:** 거래 후 또는 주간 점검 때 아래 화면을 사용한다. 원칙 준수율, 최근 거래, 반복 경고를 중심으로 보여준다. 견본의 ‘AI 모의전략 수익률 비교’는 동일 기간·초기 자금·비용·체결 조건을 갖춘 별도 전략 시뮬레이션이 있을 때만 표시하며, 초기 버전에서는 ‘당시 AI 예측과 실제 가격 변화’로 대체한다.

## 7. 핵심 완료 기준

| 항목 | 완료 기준 |
|---|---|
| AI 예측 | 시간 순서 기반 시험에서 기준모델과 비교하고, 방향 성능·확률 검증 결과·판단 보류 비율 보고 |
| 뇌동매매 탐지 | 4개 유형별 정상·위험·경계값·계획 예외 사례 검증. 시나리오 재현율 90% 이상을 목표로 하고 오탐률·정밀도도 함께 보고 |
| 모의주문 | 100건 이상 시나리오에서 기대한 접수·거절·체결 상태의 정확 처리율 99% 이상, 중복 체결 0건 |
| 시세 반영 | 테스트 환경에서 데이터 수신 후 화면·분석 반영 평균 2초 이내 |
| 사용자 경험 | 10명 이상 테스트, 핵심 기능 만족도 평균 4.0/5.0 이상 |

제안서의 ‘수익률 10% 이상 증가’는 탐색적 평가 항목으로 남기고 필수 완료 기준으로 삼지 않는다. 본 프로젝트의 핵심 성과는 **예측을 검증 가능한 형태로 제공하고, 뇌동매매 경고의 이유를 설명하며, 사용자의 계획 준수 여부를 기록하는 것**이다.
