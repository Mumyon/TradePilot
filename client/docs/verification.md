# 검증 및 재검증

검증일: 2026-10-06. Flutter 3.47.6 / Dart 3.13.5 / macOS arm64.

## 자동 검증

- Dart 정적 분석: `dart analyze` — 문제 없음.
- `flutter test` — 13개 통과.
  - 390×844 모바일 화면에서 관심종목 → 종목 AI → 주문 점검 → 최종 확인 → 접수 위젯 흐름.
  - 62% 예측의 방향 판단 보류, 잘못된 확률 합 거절.
  - 서버 접수 후 응답 유실 시 동일 키로 재확인하여 데모 중복 접수 없음.
  - 컨트롤러 재생성 시 미확인 주문 복원 및 동일 키 유지.
  - 보안 저장소 테스트 대역에서 사용자별 주문 분리 및 토큰 삭제 후 기록 유지.
  - TradePilot OFF여도 필수 점검 수행.
  - 오래된 시세에서 신규 주문 방지, 연결 중단 중 주문 전송 방지.
  - REST 인증·Idempotency-Key·정수 금액 문자열, 401 토큰 제거 및 자동 재시도 없음.
  - 로그인 성공 시 서버가 반환한 계정 ID와 토큰 저장.
  - 실제 로컬 WebSocket 서버에서 구독·이벤트 수신·연결 종료 후 새 티켓 재접속.
- Android 디버그 APK: `flutter build apk --debug --target-platform android-arm64` 성공.
  결과: `build/app/outputs/flutter-apk/app-debug.apk` (데모 기본 모드, ARM64).
  빌드 성공을 확인했으며 기기 설치·실행은 아직 하지 않았음.
- iOS 빌드: 미실행. 현재 환경에는 Command Line Tools만 있고 전체 Xcode가 없음.
- FastAPI/PostgreSQL 통합: 미실행. 서버가 아직 제공되지 않았고 API는 제안 계약임.

## 사용자가 재검증할 흐름

1. 데모 모드 실행 후 상단의 `데모 · 가상 데이터` 표시를 확인합니다.
2. 관심종목에서 삼성전자를 선택하고 시세 갱신·기준 시각을 확인합니다.
3. AI 확률 `62 / 24 / 14%`가 `방향 판단 보류`로 표시되는지 확인합니다.
4. 모의 매수에서 가격·수량을 입력하고 TradePilot ON/OFF를 바꿔봅니다.
5. 11주 주문은 데모 검사에서 차단되고, 1주는 최종 확인 후 `접수`로 표시되는지 확인합니다.
6. 매매일지에서 접수가 체결로 잘못 표시되지 않는지 확인합니다.
7. 앱을 background로 보낸 뒤 돌아와 시세가 다시 갱신되는지 확인합니다.
8. 실서버 연결 시 네트워크 차단·재연결·응답 유실·동일 키 재요청을 별도 검증합니다.

## 서버 연결/배포 전 남은 검증

- 제안 REST/WS 계약과 실제 FastAPI OpenAPI의 일치.
- DB 트랜잭션·행 잠금·중복 주문 키 고유 제약·동시 주문 테스트.
- 모델 근거·검증 성능·시점 데이터가 원래 요구사항과 일치하는지 검증.
- iPhone 및 Android 실기기의 키보드·접근성·보안 저장소·TLS·화면 크기 확인.
- 미확인 주문은 계정별 보안 저장소에서 복원합니다. 실제 기기의 앱 강제 종료·재로그인·계정 전환으로
  네이티브 저장소와 서버 키 보관 정책을 함께 검증해야 합니다.
- 데모에는 실제 잔액·체결 엔진·행동 탐지 모델이 없으므로 서버의 정확성을 입증하지 않습니다.
